# 月下圆桌 V3

用于朋友线下聚会的狼人杀与阿瓦隆手机网页。V3 在 V2 的真实多人同步、隐藏身份、技能结算与 CloudBase 部署基础上，加入警长、遗言和湖中仙女，重排手机圆桌，并修复中文输入与网关限流问题。

**手机解压后先打开 `START-HERE.html`。** 它包含运行参数、CloudBase 操作与上线验收；纯文本版见 [DEPLOY-CLOUDBASE.md](DEPLOY-CLOUDBASE.md)。项目需要运行 Node.js 服务，不能只上传到静态网站托管。

## 本桌新增规则

### 狼人杀

警长和遗言开关默认开启，房主开局前可调整。警长是公开职务，不占身份牌，也不把平民变成神职；屠边仍按原秘密身份类别判断。

首夜全部技能先结算并保存待公布结果，再竞选警长；尚未公布的死者在此时仍可参与竞选。竞选报名60秒，全员表态可提前结束。两名以上候选现场发言，房主开票；候选不投票，警下每人一票。首轮平票仅再PK一次，沿用本次警下选民；再次平票、全弃权或无人有投票资格，均无警长。

当选警长只在有资格参加的普通放逐／放逐PK投票中拥有1.5票，竞选票始终1票。警长可公开最多两个目标的警徽流，但这是玩家声明，服务端不会自动泄漏任何人的私人查验结果。

死亡及猎人效果完成后再检查胜负。仍未终局时，出局警长先移交警徽或撕毁，30秒未操作自动撕毁；随后按座位顺序安排首夜出局者遗言，或安排白天被放逐者遗言。每人60秒，可本人结束，房主可二次确认推进。后续夜晚出局者和白天被猎人带走者无遗言。已经达成胜负时直接终局，不额外拖延遗言。

### 阿瓦隆

湖中仙女不是第九张秘密身份，而是公开标记。8–10人默认启用，可关闭；5–7人自动停用。初始持有者是首任队长右手位，本桌用座位号逆序前一位表示。

第2、3、4项任务结算后，若尚未三次成功／失败，持有者选择另一位玩家，只获得其真实阵营，不获得具体身份；莫德雷德同样会被查为邪恶。不能选自己或曾使用过仙女的人。查验后标记交给目标，使用者进入不可回验名单。

公开信息只包含持有者和查验关系。阵营结果及本人历史只发给本次查验者；结果展示20秒，查验者可提前继续。房主只能确认跳过等待，不能代选目标或读取结果。三次成功直接进入刺杀，三次失败直接终局。完整终局复盘才公开仙女查验明细。

## 356条学习内容

| 类别 | 身份范围 | 数量 |
| --- | --- | ---: |
| 策略锦囊：背景、战术、误区、思考题 | 狼人杀6身份 | 每身份12组，共72组 |
| 术语配对 | 狼人杀6身份 | 每身份12条，共72条 |
| 情境挑战 | 狼人杀6身份 | 每身份12题，共72题 |
| 身份与等待小锦囊 | 双游戏14身份 | 每身份10条，共140条 |

每个位置使用独立洗牌抽取：一轮用完前不重复，新一轮开头避开上一条。同晚同步不打乱内容，下夜更新，支持主动换一条。案例选项和术语干扰项随机排列，但同晚重绘不反复变化。正常刷新会延续本机当前浏览器会话的牌堆历史；关闭会话、禁用或清空存储后重新开始。

学习和真实技能完全隔离，不会暗中查验、投票或用药。案例里的人物与座位是虚构示例；战术建议是可讨论的推测，不是系统证据。窄屏可用“展开”阅读完整讲解。导入时的校正规则见 [V3-NOTES.md](V3-NOTES.md)。

## 运行与测试

需要 Node.js 24，无第三方npm运行依赖。

```bash
npm start
npm test
STORAGE_DRIVER=snapshot node --test test.mjs v3-rules.test.mjs v3-online.test.mjs
```

本地默认使用SQLite和 `data/moon-table.sqlite`。CloudBase镜像默认使用持久快照模式，必须挂载可写CFS。生产后台密码通过环境变量设置，至少12字符。

当前测试覆盖核心规则、真实独立Cookie会话、警长遗言跨重启、仙女私密结果、原有完整终局、代理头信任、独立限流、中文组合态与输入节点保留。DOM合约与高度约束检查不等同于真实浏览器验收。当前环境的浏览器预览通道不可用，尚未完成手机实机视觉、实际IME键盘和CloudBase线上验收；部署后请按指南进行双手机及完整人数测试。

## CloudBase 与 V2 数据兼容

继续使用容器型云托管、Dockerfile、3000端口、单活动实例和CFS，保留挂载校验、进程锁、健康检查及SSE心跳。不支持横向多副本或新旧版本同时接流量。

空房间从V2读取时会补齐V3配置。已有进行中V2对局保持原游戏设置，不在中途插入警长／遗言／仙女；下一局使用新配置。旧头像默认按昵称显示。改版不会自动迁移SQLite为JSON，更新前保留原存储驱动和备份，按部署指南停旧实例后更新。

默认不信任转发IP头。常规操作、入座、恢复和后台尝试均按浏览器会话分别限流，不再把所有人并入网关内网IP的低阈值桶。仅需解析真实客户端地址时，配置 `TRUSTED_PROXY_CIDRS` 和 `CLIENT_IP_HEADER`；空值默认不信任。不要把所有地址都设为可信代理。后台密码校验改用异步scrypt，最多4个并行验证，忙时短暂返回503，不设置全站失败锁。
