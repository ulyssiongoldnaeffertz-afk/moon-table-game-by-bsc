本指南对应 V3 源码，适合只有手机的使用者。你需要在自己的腾讯云账号中完成服务创建、文件上传和参数配置；源码包不包含云账号或密码。手机控制台按钮位置可能因屏幕和版本变化，必要时在浏览器中切换“桌面版网站”。

先记住这一套搭配：CloudBase 容器型云托管，Dockerfile 构建，3000 端口，一个持续运行实例，CFS 读写持久挂载。 这是本项目的支持配置。两种游戏各三个房间，总共六张圆桌，不需要创建六个云服务。

先把文件准备好

  1. 下载源码 ZIP，在手机的文件管理器中解压。
  2. 打开解压后的目录，确认同一层能看到 Dockerfile、server.mjs、package.json 和 assets 文件夹。
  3. 原样保留所有运行文件，尤其不要漏掉三个 WebP 插图与 learning-data.mjs。
  4. 上传时选择这层目录作为项目根目录。不要把 ZIP 上传到静态网站托管后直接打开，也不要把 Dockerfile 的内容粘到“启动命令”。

源码运行不需要 npm install、不需要前端打包，也不需要你在手机安装 Node.js。Dockerfile 会在云端准备 Node.js 24 与文件锁工具。

创建环境和持久存储

  1. 用手机浏览器进入 CloudBase 控制台 ↗，登录自己的腾讯云账号，按控制台提示创建或选择一个环境。
  2. 进入“云托管”，选择支持 Dockerfile 的容器型服务。它不是“函数型云托管”。
  3. 记录服务所用地域，在该地域准备一个 VPC 和子网，并在 CFS 控制台创建文件系统。按 CloudBase 的存储挂载页面要求让服务与 CFS 使用相同 VPC、子网。优先使用支持 NFS v4 文件锁的挂载。
  4. 在云托管服务的“私有网络”中配置上述 VPC、子网。
  5. 在“存储挂载”中启用文件存储 CFS，选中正确的文件系统与挂载点，权限选读写，实例挂载路径填 /mnt。
  6. 项目的 DATA_DIR 设为 /mnt/moon-table。程序会在 /mnt 里创建 moon-table 子目录。

如果创建服务后才能看到挂载设置，可先保存服务，配置好 CFS 后再启动正式版本。尚未挂载时，容器主动拒绝启动是正常保护行为，不应通过关闭检查来绕过。

CFS、容器和网络资源可能产生费用，请以控制台实际计费为准。本指南不假设免费额度，也不要求购买高规格实例。

上传与启动

  1. 在云托管部署页选择从源代码部署，按页面支持方式上传含 Dockerfile 的项目目录。腾讯云当前文档提供“文件夹”上传；若手机浏览器无法选择文件夹，使用桌面版页面重试。
  2. 手机浏览器仍不支持文件夹上传时，可把解压后的源码上传到自己有权限的 Git 仓库，再使用 CloudBase 的 Git 仓库部署。仓库根目录仍须能直接看到 Dockerfile。控制台具体支持的来源以页面为准。
  3. 检查上表配置、CFS 挂载和密码，然后点击部署。
  4. 在构建日志中确认镜像构建成功，在运行日志中看到“月下圆桌已启动，监听 0.0.0.0:3000”。
  5. 打开服务的默认 HTTPS 域名，看到大厅与三张卡通插图。访问同域名的 /healthz，应显示 ok。
  6. 在房间里尝试填写昵称入座。不要在 PUBLIC_ORIGIN 错误时反复重置房间，应先修正域名配置。

不要覆盖镜像入口点为 node server.mjs 或 npm start；否则会绕过持久挂载与单写入进程保护。不要用启动多个副本来排查失败。

V3 的代理与升级配置

V3 常规操作、入座、恢复与后台登录尝试按浏览器会话分别限流。默认不信任任何转发IP头；即使同一CloudBase网关内网地址承载全部玩家，也不再共享原来的8次后台失败或低阈值入座桶。

可选环境变量默认值什么时候填写
TRUSTED_PROXY_CIDRS空仅当你确认代理实际回源地址／网段，且其正确覆盖或追加客户端地址时填写，逗号分隔
CLIENT_IP_HEADERx-forwarded-forCloudBase链路可能需用 x-original-forwarded-for，或明确的 x-real-ip；以实际网关配置为准

程序只在socket对端属于可信网段时解析指定请求头，并从右向左剥离可信代理，遇到首个非代理地址即停止。不盲信最左侧IP，不用所有私网地址或 0.0.0.0/0 代替实际信任配置。即使不配置这两项，会话限流仍然独立；无需为了正常聚会猜测网关IP。

后台验证改为异步scrypt，最多4个并行验证。忙时返回短暂503，不把全站失败次数当作账号锁。对大量丢弃Cookie的脚本，仍需你自己的网关防护；项目不会声称仅靠浏览器会话能阻止所有恶意流量。

从V2更新请先备份、结束对局并停止旧实例。继续使用原来的CFS路径及snapshot驱动。空房间补齐新开关；进行中的旧对局保留原流程，下一局才使用新规则。不要把SQLite文件直接改名，也不要让新旧两个进程同时写同一快照。

数据与重启

CloudBase 数据存于 CFS 的 /moon-table/moon-table.snapshot.json（挂载到容器中对应 /mnt/moon-table/moon-table.snapshot.json）。它包含房间、身份状态和有权限的归档信息，不要把它放进公开仓库或分享给玩家。

每次有效变更都会先写完整临时文件、同步文件，再在同目录原子替换快照。房间和新归档一起提交。实例重启后从此文件恢复服务端状态，并按照当前服务器时间推进已经到期的阶段。

狼人临时聊天、在线状态与管理后台会话不持久化。重启后聊天为空，玩家重新建立在线状态，管理者重新登录。夜晚倒计时不会因重启自动重新给足三分钟。后台登录密码本身也不会被写入快照。

日常备份可以使用 CFS 提供的备份或快照能力，也可在停止游戏与写入实例后复制整个 moon-table.snapshot.json。恢复前停止所有写入实例，再把备份放回同一路径，然后只启动一个实例。不要在游戏过程中手动编辑 JSON。

本地模式继续兼容第一版 SQLite 文件；云托管 snapshot 模式不会自动读取第一版 SQLite。若已有运行数据，应在停服后另行迁移；不要直接把 SQLite 文件改名为 JSON。本次附件没有提供运行数据库，因此交付包从空房间开始。

更新版本

这一版使用单活动进程维护游戏，更新允许短暂停服，不支持滚动零停机或灰度分流。CloudBase 的“最大 1 实例”是按版本计算的，存在新旧两个版本时仍可能同时出现两个实例，因此仅填写最大实例数不够。

  1. 在没有进行中对局时更新，先备份 CFS 数据。
  2. 暂停对外游戏。在控制台把服务切到可手工启停实例的模式，确认旧版本实例不会被自动重新拉起。
  3. 通过实例列表“停止实例”，停止旧版本的唯一运行实例，确认进程已退出并释放文件锁。保留原 CFS 与挂载目录。
  4. 部署新代码或新的环境变量，确保新版本沿用相同 CFS、相同 DATA_DIR、相同密码和实际域名配置。
  5. 在版本列表只启动新版本的一个实例，将流量指向新版本。健康检查通过后，再按控制台支持方式恢复“持续运行 1 实例”。检查旧版本没有运行实例，也没有分流。
  6. 用原浏览器刷新，确认房间与历史恢复，然后让朋友重新进入。

如果新版本日志出现退出码 75，说明有另一个进程持有同一数据目录的锁。回到实例列表确认并停止旧进程，然后重启新实例。不要删除锁文件来强行绕过；只要旧进程完全退出，内核锁会自动释放，锁文件本身留在目录里是正常现象。

如果控制台无法按以上方式停止旧实例或控制单活动版本，先保持当前服务，向腾讯云支持确认该环境的实例启停能力，不要用同时运行两个版本的方式继续上线。未来若需要自动横向扩容，应改成外部事务数据库与共享的临时消息/会话机制；当前源码不宣称具有这些能力。
